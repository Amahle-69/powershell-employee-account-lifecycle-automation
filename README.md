
# PowerShell Employee Account Lifecycle Automation

## Project Overview

This project demonstrates how PowerShell can help an IT Support team validate employee records and prepare onboarding and offboarding reports using structured CSV data.

The project uses a fictional company, Mahlangu Business Solutions, to simulate routine employee account administration workflows.

The initial version runs locally with fictional employee data. It does not create, disable, modify, or delete actual user accounts.

## Business Problem

Human Resources may supply employee CSV files containing incomplete records, malformed email addresses, or duplicate employee IDs.

Manually checking these files can introduce errors and delay onboarding or offboarding preparation.

This project automates data validation and produces reports that help authorised IT staff identify records requiring review.

## Features

- Imports employee records using PowerShell's `Import-Csv`.
- Verifies required CSV headers.
- Identifies missing required fields.
- Checks basic email address formatting.
- Detects duplicate employee IDs.
- Validates employee status and date fields.
- Exports employee validation results to CSV.
- Generates onboarding review reports.
- Generates offboarding checklists.
- Includes automated tests for expected validation and reporting results.
- Keeps account creation and account disablement outside the current implementation.

## How to Run the Project

Open PowerShell in the project root directory.

### 1. Validate employee data

```powershell
.\scripts\Import-EmployeeData.ps1
```

This imports the HR CSV, validates the records, displays the results, and writes:

`reports/employee-validation-report.csv`

### 2. Generate the onboarding review report

```powershell
.\scripts\Export-OnboardingReport.ps1
```

This creates an onboarding review report for new-starter records that pass the current validation rules.

### 3. Generate the offboarding checklist

```powershell
.\scripts\Export-OffboardingChecklist.ps1
```

This creates a manual-review checklist for eligible offboarding records.

### 4. Run the employee validation tests

```powershell
.\tests\Test-EmployeeData.ps1
```

### 5. Run the lifecycle report tests

```powershell
.\tests\Test-LifecycleReports.ps1
```

These results describe the current sample data and test runs; they are not a guarantee that every possible input has been tested.

## Safety and Limitations

- All employee names and records are fictional.
- The email addresses use reserved example addresses.
- The email validation is a basic format check, not proof that an address exists.
- `ReadyForReview` means only that the record passed the implemented validation rules.
- Duplicate IDs are flagged for review rather than automatically resolved.
- Onboarding and offboarding reports are checklists, not proof that approvals or actions have been completed.
- No real Active Directory accounts are created or modified.
- Production use would require additional requirements, permissions, security controls, and testing.
